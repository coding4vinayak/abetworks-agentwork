# Framework infrastructure expansion: events, LLM, plugins, persistence, observability, WebSocket, rate limiting, CLI

This change adds eight new subsystems to the agentwork framework: an event bus for pub/sub messaging, a provider-agnostic LLM abstraction, a runtime plugin system, a SQLite-backed persistence layer, an observability stack (structured logging, metrics, tracing), WebSocket support for real-time streaming, a token-bucket rate limiter, and a CLI. It also adds company presets, a task-aware orchestrator, and a fleet API for remote orchestration with task-ID tracking. The change spans 78 files adding ~8000 lines, with 168 new tests (436 total passing).

Watch for: the fleet API `/fleet/orchestrate` endpoint blocks the ASGI worker synchronously for the entire DAG execution duration (confirmed); the rate limiter and WebSocket manager use unbounded in-memory dicts with no eviction or max-client limit (confirmed); the SQLite backend uses a single connection with no thread-safety guarantees for concurrent access (confirmed); the event bus silently drops async handlers when called from `publish()` inside a running event loop (confirmed).

## High-level view

The event bus provides fire-and-forget pub/sub with fnmatch-based wildcard subscriptions and bounded history. Its primary gap is behavioral asymmetry: `publish()` silently drops async handlers when an event loop is running (the most common case in an async application), which means in a FastAPI context most async subscribers will never fire.

The `PromptTemplate` delegates to Python's `str.format()` with no sandboxing. If user-supplied data ever reaches template variables, format-string attribute access (`{name.__class__}`) permits information disclosure.

The plugin system loads arbitrary Python modules by dotted path or file path and scans them for `Tool` instances. The hot-reload path (`reload()`) calls `unload()` then `load()`, but imported modules remain in `sys.modules`, so `importlib.import_module` returns the cached version — hot-reload silently does nothing for package-path plugins.

The SQLite persistence layer creates a single `sqlite3.Connection` in `__init__` and reuses it for all operations without threading protection. The default `check_same_thread=True` means cross-thread usage raises `ProgrammingError`. The `CacheManager` and `KnowledgeBase` in the same PR correctly use threading locks, making this an inconsistency.

The `MetricsCollector` stores histograms as unbounded append-only lists of float values — in a long-running process, this grows linearly with traffic without any rotation or export-then-flush cycle.

The fleet API's `/fleet/orchestrate` endpoint runs the orchestrator synchronously, blocking the ASGI worker thread. In a multi-user deployment, a single slow orchestration starves all other requests.

The rate limiter stores buckets in an unbounded `dict` — each unique client IP or API key adds an entry that is never evicted. Under sustained traffic from many distinct clients, this grows without bound.

The WebSocket manager has no connection limit, no idle timeout, and no heartbeat. A misbehaving client can open thousands of connections, and silent disconnects (network partitions) leave stale entries that leak memory and cause failed `send_json` calls on every broadcast.

1. **Sync orchestrate blocks ASGI worker** — `POST /fleet/orchestrate` executes the entire DAG synchronously on the request thread. Wrap in `asyncio.to_thread()` or use FastAPI's `BackgroundTasks` to avoid starving the event loop.
2. **EventBus drops async handlers in running loop** — `publish()` skips async handlers when an event loop is already running (the normal case in FastAPI/asyncio apps). 3. **SQLite single-connection thread safety** — `SQLiteBackend` creates one `sqlite3.Connection` in `__init__` and uses it from any thread. Add `check_same_thread=False` and a threading lock, or use a connection-per-thread pattern.
4. **Rate limiter unbounded bucket dict** — `RateLimiter._buckets` grows without bound. Add a max-clients cap or periodic eviction of stale entries.
5. **WebSocket manager no connection limit** — `WebSocketManager._connections` accepts unlimited connections. Add a max-connections threshold and reject new connections when exceeded.
6. **MetricsCollector histogram memory growth** — `_histograms[key]["values"]` is an append-only list. Add rotation (keep last N values) or periodic flush to an exporter.
7. **Plugin hot-reload doesn't clear sys.modules** — `Plugin.reload()` calls `unload()` + `load()` but never removes the module from `sys.modules`, so `importlib.import_module` returns the cached module. Use `importlib.reload()` on the cached module to pick up file changes.
8. **PromptTemplate format-string injection** — `PromptTemplate.render()` uses Python's `str.format(**kwargs)`, which allows attribute access (`{name.__class__}`) on injected values. If user-supplied data is ever passed as template variables, this permits information disclosure. Consider using `string.Template` (safe substitute) or restricting to simple field names.

## Event bus: async handler drop in running loop

The `publish()` method detects async handlers and tries to call `asyncio.run(handler(event))`. When an event loop is already running (which is always the case inside a FastAPI request or any `async def`), it logs a debug message and skips the handler entirely:

```python
try:
    loop = asyncio.get_running_loop()
except RuntimeError:
    loop = None
if loop and loop.is_running():
    logger.debug("Skipping async handler %s in sync publish ...", handler.__name__)
else:
    asyncio.run(handler(event))
```

In the primary intended environment (an async web server), `publish()` silently discards all async subscribers. The `publish_async()` path works correctly, but nothing guides callers toward it — the API surface makes `publish()` look like the default. Consider using `loop.create_task(handler(event))` when a loop is running, which would fire-and-forget the handler onto the existing loop, or raise an explicit error rather than silently dropping.

## Fleet API blocks the ASGI worker

The `/fleet/orchestrate` endpoint calls `orchestrator.orchestrate()` directly inside the route handler. The orchestrator uses `ThreadPoolExecutor` internally for parallel sub-tasks, but the route itself is a sync def in FastAPI, meaning it runs on the main thread pool. For a single orchestration with a complex DAG, this blocks an ASGI worker for the entire duration.

The fix: make the endpoint `async def` and call `orchestrate_async()`, or wrap the sync call in `asyncio.to_thread()`:

```python
@app.post("/fleet/orchestrate")
async def orchestrate(request: OrchestrationRequest) -> Dict[str, Any]:
    result = await asyncio.to_thread(orchestrator.orchestrate, ...)
```

## SQLite backend thread safety

`SQLiteBackend.__init__` calls `sqlite3.connect(db_path)` and stores the connection as `self._conn`. Python's `sqlite3` module by default sets `check_same_thread=True`, meaning cross-thread use raises `ProgrammingError`:

```python
self._conn = sqlite3.connect(db_path)  # check_same_thread=True by default
```

Pass `check_same_thread=False` and add a `threading.Lock` around all cursor operations (matching the pattern used in `CacheManager` and `KnowledgeBase`), or create a new connection per operation.

## Rate limiter unbounded memory

`RateLimiter._buckets` is a plain `Dict[str, Tuple[float, float]]` with no eviction. In a deployment behind a CDN or load balancer that passes varying `X-Forwarded-For` headers, or in an API with many distinct API keys, this dict grows indefinitely. The companion `CacheManager` and `_LRUOrchestrationStore` both implement bounded stores — the rate limiter should follow the same pattern.

## WebSocket manager lacks connection bounds and cleanup

`WebSocketManager._connections` is an unbounded dict of lists with no max-connection enforcement, no idle timeout, and no heartbeat. The disconnect logic is purely reactive — it fires only when the client closes the connection or an exception occurs during receive. A client that connects and then goes silent remains in the connection list indefinitely, leaking memory and causing failed `send_json` calls on every broadcast.

## Plugin reload semantics

`Plugin.reload()` calls `self.unload()` then `self.load()` which calls `self._import_module(entry_point)`. For dotted-path imports, `importlib.import_module` returns the already-cached module from `sys.modules` without re-executing it. For file-path imports, `spec_from_file_location` re-executes the file because it uses a dynamic module name (`_plugin_module`). This inconsistency means hot-reload works for file-path plugins but silently does nothing for package-path plugins. Fix: store the loaded module reference and use `importlib.reload(module)` on subsequent loads.

## MetricsCollector histogram growth

Each call to `collector.histogram(name, value)` appends to an in-memory list:

```python
self._histograms[key]["values"].append(value)
```

At 1000 requests/second, that's 86 million float values per day per metric name (~700MB). There's no rotation, no downsampling, and no export-then-flush cycle. The `reset()` method exists but must be called manually.
